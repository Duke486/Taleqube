# 匹配与内容映射

## 两层匹配

身份匹配确定来源作品对应的 TMDB 影视或 AniList 书籍主条目。已有确认身份优先复用；新候选由 AI 判断或用户手动确认。搜索无结果或候选被排除时，可通过 AI 和联网搜索补充别名再搜索。书籍匹配还检查漫画／小说、系列／单卷等类型信息。

季集匹配以 TMDB 为坐标，将平台条目映射到实际季和集。`ContentMapping` 保存覆盖季、集对应组、完整性、证据和人工确认状态，并校验真实坐标、重复与越界。季归属和集对应独立：只确认季时可以使用季评分，进度需要相应的有效映射。

## 多轮补证

`SeasonMatcher` 对每个作品／平台最多进行六轮判断（含首轮）。普通候选先使用轻量搜索元数据和 TMDB 季列表；必要时读取平台详情、TMDB 集表，按缺项联网搜索并继续判断。首轮否定是暂定结果；未给研究计划时程序补充有预算的调查，证据停滞进入最终裁决。清晰关系可以提前结束；已配置 OpenAI 时最终裁决使用 Terra，允许依据现有资料合理推断，仍需校验真实坐标。

完整的一对一正片季在该平台没有其他条目覆盖同一季、且已知平台集数不冲突时默认逐集对应；拆季或跨季自动尝试集对应，“AI 补全集对应”保留为重试入口。季相关 OVA／OAD／SP 单独比对实际 S00 集标题、简介及平台简介，无法确定具体集时跳过；独立 OVA 不因发行形式自动归入特别篇。

## 保存与投影

普通匹配保留人工锁定并补齐新条目；显式重新匹配刷新资料，释放所选范围内的旧锁定并重新判断。已确认结果按平台保存，部分确认时保留尚未确认的旧关联；后续失败或取消不撤回已保存的平台。集映射未完成不阻塞季归属保存。

同步将 TMDB 观看进度投影为平台自己的连续已看前缀；合并集要求所有对应集完成，完整映射且内容全部完成才将平台条目标为完成。季评分按覆盖范围继承；跨季评分不一致时不取平均。映射本身不新增单集观看操作。

变更匹配逻辑前先阅读 [匹配与内容映射](匹配与内容映射.md) 和 [贡献约束](贡献约束.md)，保留用户指定的多轮、补证、模型裁决和自动集匹配能力。

## 排查入口

- `SeasonMatcher.match` 管理状态及终态；`performMatch` 负责候选搜索、模型轮次和研究请求。
- `MatchTurn`、`MatchDecision` 和 `MatchResearch` 解码模型输出；候选 ID、证据 ID、真实季集和映射重复项由程序校验。
- `ContentMapping.validate` 校验覆盖和编号；`TrackingRecord.mappedPayload` 将对应关系投影为平台进度。平台首集未映射时暂停进度，避免把未知开头误写为零。
- `WorkSheet.performFindAssociations` 组织逐平台调用与保存；`TrackingStore.saveAssociations` 持久化关联并使不再适用的待同步任务失效。
- 用户手动更换平台条目后，原集映射不能转用于新条目，需重新确认。
