# Taleqube

原生 SwiftUI 电影、剧集与书籍资料库，支持 iPhone / iPad，以及使用 iPad 界面的 Apple 芯片 Mac，目标 iOS / iPadOS 27+。设备直接访问平台 API。

## 运行

使用 Xcode 27+ 打开 `Taleqube.xcodeproj`，设置签名团队与 Bundle Identifier。

在 Apple 芯片 Mac 上运行时，选择 `My Mac (Designed for iPad)` 运行目标，使用现有 iPad 界面。

```sh
./Scripts/build-simulator.sh
./Scripts/check-core.sh
./Scripts/check-tracking.sh
./Scripts/check-language.sh
./Scripts/check-matching.sh
./Scripts/check-season-matching.sh
```

## 资料库规则

- 电影、剧集以 TMDB 为主条目；漫画以 AniList 为主条目，不提供主数据源选择器。
- 浏览、搜索、读取平台片单、关联平台均不会自动入库。只有在应用内保存评分／状态或明确选择入库才建立本机资料库记录。
- Trakt、AniList 片单使用独立页面，保存平台自己的观看进度与评分；侧栏进入这些页面不会修改资料库分类。
- 从平台导入时逐部排队，保留逐项确认。影视先使用已有 TMDB 身份，否则按标题搜索，由 AI 从候选中确认身份；搜索无结果才由 AI 生成多组标题并从聚合结果中选择。详情打开优先复用持久化的 TMDB 主身份和资料，不刷新匹配；只有尚无已确认身份才执行匹配流程。详情在横图右下角提供 AI 与铅笔两个 44 点液态玻璃圆形按钮，分别执行 AI 匹配 TMDB 与手动选择，按钮底边距横图底边 8 点；AI 匹配期间显示加载状态，手动选择可取消当前匹配。导入保留文字操作入口，两处均可修正身份；漫画使用 AniList。已入库作品可在详情内更新匹配，保留本机评分和进度。平台片单按直接关联及已保存的主身份判断已导入，并从批量导入列表排除；移除片单的“校正已入库匹配”入口。导入以来源／主平台两张卡片比较，AI、手动、跳过和确认操作固定在底部，每项切换重置正文位置。
- 导入不向远端回写。重复导入保留已有本机评分与状态；多个平台／季度归入同一主条目时保存各自的来源进度。旧版特例获得主条目关联后即时迁移身份。
- 详情只显示真实季，第一季、第二季等在前，特别篇在末尾；首次默认第一季。平台新增条目支持多选，跨查询与分页保留选择；新增关联默认为待确认，同平台允许多个条目。内容对应以 TMDB 季／集为准，支持拆季、跨季、连续区间以及一集拆多集／多集合一集。旧自定义关联按原兼容规则迁移，新版待确认映射不会被自动转为整部。
- 详情默认编辑整部评分，季评分在季切换器下方的整合卡片中编辑。仅覆盖一个 TMDB 季的条目（包括拆分部分）优先使用该季评分，否则继承整部评分；清除季评分恢复继承。跨季条目仅在各季有效评分相同时同步，不做平均；可明确选择使用整部评分。TMDB、Trakt 和其他整部关联只使用整部评分。保存自动同步评分、状态或进度的变化，纯评分任务不提交状态与进度。同步失败保留本机保存；重试读取最新记录，逐次保留提交值、步骤与错误。Bangumi 和 Trakt 支持已看进度回退及归零，更换或移除关联后失效任务不再执行。


## 分层匹配与内容映射

- 关联页及每个拆季平台的匹配按钮旁提供“重新匹配”。普通匹配保留人工确认和旧版已有关系、补齐新条目；重新匹配刷新 TMDB 季与平台资料，不锁定旧关系，完成后整体替换所选范围内的关联。按平台即时提交已确认的季关联；集对应未完成不阻塞保存。季归属全部确认后才替换旧集合，部分确认时合并结果并保留未确认的旧关联。后续平台失败或取消不撤回已保存平台。评分、已看记录与同步开关保留，不自动向远端提交。
- `SeasonMatcher` 每个作品／平台最多六轮模型判断，包含首轮。普通条目首轮只传搜索元数据和 TMDB 季列表；OAD／OVA／SP 特别篇额外读取平台详情及 TMDB S00 集标题和简介，第一轮仍无法确定具体 S00 集号时直接跳过，不继续联网追查；完整一对一季关系由程序默认逐集对应，拆季与跨季自动读取平台详情及 TMDB 集表并进入集匹配；“AI 补全集对应”保留为重试入口。普通候选首轮排除仅作暂定，未匹配且模型未给出研究计划时补充一次有预算的详情／搜索，证据停滞进入最终裁决。后续查询由模型围绕具体缺项提出，程序执行去重、预算、身份与引用校验；无新信息进入最终取舍；最后一轮使用已配置的 Terra，允许根据现有标题、简介等作合理推断，仍无法确定的条目放弃关联。连续格式错误最多修复两次且占用轮次；临时网络错误最多重试一次。
- 默认 `deepseek-flash`，常规匹配及补证关闭思考。图片集表仅从已登记网页证据提取后按需传入视觉输入，不默认发送海报。复杂或冲突证据、补证后无进展时升级 `gpt-6.1-terra`，升级后继续使用 Terra 完成剩余处理；Terra 明确设置 reasoning_effort 为 none（常规判断）或 low（复杂对应），low 另留 4,096 tokens 思考预算；界面与诊断显示实际模型和升级路径。模型返回结构化研究请求，由应用调度 HTTP 工具，不使用 Chat Completions 原生函数调用。
- TMDB 只有 S01 与可选 S00 时，普通单条目可建立整部关联，但覆盖固定为 S01；不默认包含特别篇或未来新季。季归属和集映射独立：可先继承季评分，集映射不足时暂停进度，已验证的部分映射保留并继续补全。人工仅确认季归属后仍可使用 AI 补集。关联卡片显示依据、评分来源和映射状态，支持“AI 补全集对应”和人工内容对应编辑。
- 请求按任务设置输出上限和超时，详情与集表最多三个并发。每个平台采用 360 秒软预算，在轮次与补证边界停止并返回已确认结果；全平台操作硬上限 1800 秒。界面显示模型、阶段和已耗时，结束状态显示保存数量、集映射数量与停止原因，计时器不能覆盖最终结果。共享名称／简介请求按订阅者取消，最后一名调用者取消时终止网络请求。诊断记录耗时、输出结束原因、token 用量、思考 token 用量与字段校验路径；未匹配决定允许省略无意义的季坐标，匹配成功仍严格校验范围。
- 映射使用版本化 `ContentMapping`，记录 TMDB 身份、明确覆盖的季、平台总集数、完整性、集对应组、证据和人工确认状态。程序校验真实季、实际集表、重复／越界编号与完整覆盖。连续区间在人工编辑器中展开为明确集关系；不以相同集数推断偏移。
- 同步从 TMDB 已看集投影为平台自己的连续已看前缀；合并集要求所有对应集完成。平台条目仅在完整映射且全部内容看完时标记完成。评分与进度分别排队、分别校验，跨季评分冲突不阻塞有效进度。映射变更使旧待同步任务失效，重试重新读取最新关系与个人记录。
- 未解决结果保留明确原因，已确认季归属可独立保存；新映射不会自动升级为未知整部范围。取消、人工修改、主身份改变或落盘失败均不能留下半套新关系。

## 界面与发现

- iPad 顶部导航依次为首页、发现、资料库，以及固定在末尾分组的 AniList、Trakt；两个平台各自直接切换页面，不折叠为“平台”菜单，主栏目与平台入口之间使用系统标签栏分隔。
- 首页包含背景海报轮播，以及最近观看、最新入库影视／漫画、继续观看／阅读、平台推荐和每日资料库随机挑选；每个栏目单行横向滚动。详情展示背景海报、图片画廊、按季加载的剧集图，支持全屏浏览缩放。
- iPad 主导航使用系统 `TabView` 的 `sidebarAdaptable` 样式，初始显示侧边栏；点击左上角切换按钮切换为顶部 Tab，再点顶部导航最左侧的按钮恢复侧边栏，切换保留当前栏目。首页、发现、资料库和平台片单共用同一导航，iPhone 使用首页、发现、资料库三个底部标签；导航始终显示，不随滚动收起。页面使用系统导航栏与柔和渐进式滚动模糊；作品详情使用系统缩放 sheet，iPad 目标宽度 700 点。设置与同步记录在侧边栏模式位于侧栏底部，顶部 Tab 与 iPhone 模式位于页面右上角，点击区至少 44 × 44 点，两个入口共用互斥的弹窗状态；同步记录显示可清除的错误计数，清除计数保留原记录和重试能力。
- 封面网格顶端对齐，标题最多两行，年份与观看进度紧随标题，补齐留白放在文字区底部以保持卡片等高。观看／阅读状态移至封面左上角，统一两字（在看、在读、完成、计划、搁置、放弃、重温、评分），封面角标与详情状态选择共用文字、底色和边框配色，采用隔离封面颜色的不透明圆角矩形底色，状态统一为在看／在读蓝、完成绿、计划灰、搁置琥珀、放弃红、重温紫、评分青，深浅模式分别使用亮字和深字；待确认提示位于封面左下角。书籍封面右下角统一读取 AniList format、Bangumi platform 和 MyAnimeList media_type 显示角标：漫画为橙黄色液态玻璃“漫”，小说（含轻小说）为绿色液态玻璃“文”；画集、绘本、写真、公式书及未知类型不显示漫／文角标；浅色模式深字亮底，深色模式亮字深底，增加底色密度以隔离封面干扰。
- 资料库可按入库日期、修改日期从新到旧排序，也可按标题和评分排序。旧数据缺少的日期在首次读取或导入时补为当前时间并保存；备份保留两个日期字段。保存评分、进度、标题、关联与批量状态更新修改日期，刷新资料不会改变日期。书籍资料库提供全部、漫画、轻小说筛选。
- 平台片单中的已匹配影视显示 TMDB 封面与标题，标题优先使用该 TMDB 条目上保存的人工或 AI 修改；未入库但已保存匹配的条目同样生效。列表保留来源平台身份、年份、评分和观看进度，搜索兼容显示标题与来源标题。
- 本机与平台片单分开浏览影视和书籍，iPhone 在资料库的“平台片单”菜单进入 AniList／Trakt；本机资料库支持长按选择、全选、批量本机状态和确认删除，删除同时清理待同步任务。
- 详情常驻平台评分与跳转链接：按平台展示整部条目和带季标签的拆季条目，切换季后展示明确绑定该季的条目均分。平台均分与个人评分分开，关闭同步不会隐藏评分；无评分时保留链接。打开详情先显示缓存评分，再后台刷新，刷新不改变个人记录和资料库修改时间。
- 详情横图铺满容器宽度，不设圆角，保持正文中的原始高度与位置；横图顶部在 40 点范围内渐进模糊，模糊背景连续延伸至顶栏与状态栏，清晰图像不向上延伸；横图下缘对齐竖版封面中部，标题从下缘下方 8 点开始，原名与年份随标题自然排布，避免与横图右下角的匹配按钮重叠；横图底部使用硬边缘，仅在图片底层保留轻微下阴影，文字位于横图下方。书籍无横幅时，以海报作为背景，整张背景统一使用与顶部相同的 32 点模糊半径。竖版封面宽 120 点（窄栏 104 点），叠加向下投影，正文保留 20 点边距。Hero 取消额外底部留白，作品摘要、TMDB 对应身份、平台评分与入库操作以 16 点间距集中排列，独立正文分区保留 24 点间距。整部平台评分使用图标加分数的小标签，标签整体换行；季切换器下方以一张卡片集中展示本季平台评分、个人评分、继承状态、观看状态和进度。整部评分常驻，季评分直接在卡片编辑。剧集卡片使用横向懒加载，图片和简介仅加载可见区域及前后各三集；点击进入原生 sheet 浏览器，支持左右滑动、箭头与键盘翻页。剧集与剧照共用同一个浏览器组件，由系统管理液态玻璃材质、遮罩、阴影、圆角和呈现生命周期；使用来源卡片的 matchedTransitionSource 与 navigationTransition(.zoom) 缩放展开，不使用透明全屏容器和手绘玻璃面板。默认高度为可用区域的 90%，可展开到完整高度；iPad 使用 form 呈现尺寸。正文使用 20 点边距，最大宽度 800 点，图片圆角 10 点；集详情图片恢复 16:9 预览区域，图像等比例完整显示，不限制为弹窗高度的某个比例。简介随正文自然滚动。全屏图片状态与 fullScreenCover 统一由浏览器根节点持有，翻页的懒加载子视图只发出查看请求；关闭全屏只清除图片选择，保留浏览器页码与正文。黑色背景和深色环境仅作用于全屏图片视图。全屏支持双指缩放、放大后拖动与双击还原；两种浏览器均支持键盘翻页、减弱动态效果和辅助功能翻页。
- 平台关联按平台分组，在滚动容器中将每个条目独立显示为卡片，卡片使用 16 点内边距、12 点内部间距与 18 点圆角；平台分区间隔 24 点。同一条目的标题、链接、对应范围与同步开关聚合排列，仅操作区上方保留分隔线；范围菜单使用明确的行布局，避免 Form 将条目拆成独立表单行。每条的对应范围菜单、集对应编辑、同步开关、更换与移除按钮独立操作，即时保存，不提交尚未保存的评分或进度。整部评分与进度存在修改时，详情顶部显示保存按钮；未保存的进度只保留在当前详情中。底部红色“清除本作缓存”按钮会清除元数据、译文、季资料、图片和全部绑定，从本次进入详情的来源平台重新获取，再重新匹配 TMDB；保留本机已保存的评分和观看记录，移除旧待同步任务。
- 发现分为电影、剧集、动漫、书籍，影视默认 TMDB、动漫与漫画默认 AniList，每类可切换来源。TMDB 支持年份、题材、语言、评分、评分人数、时长／剧集状态、排序和分页；搜索模式使用年份。AniList 支持年份、季度、形式、状态、题材、地区、最低评分、多种排序和分页；动漫可包含动画电影。Trakt 支持榜单、年份与题材，Bangumi 支持年份季度、标签与评分，MAL 支持榜单和季度。
- 搜索与发现包含成人内容：AniList 不按 isAdult 排除条目，MAL 请求开启 nsfw，TMDB 搜索与发现开启 include_adult；关联匹配共用上述搜索。
- Trakt 读取观看与评分片单、中文元数据和图片，分页合并；全部界面图片共用磁盘缓存，默认上限 512 MB，按最近使用时间淘汰；横图地址与季资料另缓存 24 小时并跨启动保留，同作品并发请求合并，清除本作缓存同时失效；图片在缓存 actor 解码并准备显示，解码图像内存缓存上限 64 MB；设置可调整上限、禁用缓存和清理。
- 设置采用账号、翻译与匹配、数据三个固定分区。手动账号配置明确保存，未保存退出时提示；登录、断开与数据操作即时执行。⌘1／2／3 切换栏目，⌘F 搜索，⌘R 刷新。

## 搜索与中文显示

- 中文名与别名查询使用两次 AI 调用：先发送作品标题、原名、类型、年份和简介，让 AI 构造不超过 128 字符的搜索词，再调用 DeepSeek `/v1/tools/search`，最后把结果附加到作品信息发给 AI 给出中文名与别名。空结果或搜索故障也执行第二次调用，按已知译名或直接翻译补全；保存时区分联网查证、AI 已知译名和 AI 翻译来源。JSON 解析、索引、链接及长度均校验。搜索先显示原查询结果，再通过 AI 规划查询、联网检索与证据整理补充别名，重搜并去重合并；发现页、平台页和关联搜索共用此流程。
- 手动搜索和跨平台关联共用多语言搜索。详情与导入的 TMDB 匹配复用已确认身份；新候选需经 AI 判断或手动确认，不再自动采用首结果。默认匹配模型为 DeepSeek，未配置时可使用 OpenAI。自动关联、季匹配和批量导入在原搜索为空或候选全部被排除时，调用共用 AI＋联网别名流程，再按目标平台生成搜索词、重搜并确认候选。搜索词限制单行标题、数量与长度；格式修复失败后回退已有原名和标题。网络错误不视作搜索无结果，过期请求不会覆盖新的手动选择。
- 自动标题翻译每批最多 12 个，每个标题限制 120 字符，输出限制 1,600 tokens；标题请求不携带简介。输出截断时拆小批次重试。后台请求不覆盖用户手动修改。
- 简介先去除 HTML、脚本、样式及编码标签，保留换行；识别为中文时跳过翻译。翻译按钮与原文／译文切换按钮互斥。
- 标题与简介译文持久化且无过期时间，原文变化才使对应译文失效。资料库共用译名；详情允许手动改名或联网查找中文译名并保存来源。

界面浏览与后台任务分离：匹配期间保留详情浏览、切季、剧照和关闭操作，只锁定冲突编辑。网络响应 JSON 解析与常规诊断写入在后台执行；资料库身份查询使用随备份更新失效的索引，HTML 纯文本转换使用有界缓存。

## 账号与诊断

| 服务 | 配置 |
| --- | --- |
| AniList | Client ID，回调 `anishelf://oauth`，或访问令牌 |
| Trakt | Client ID，Redirect URI 为 `http://localhost`，设备授权登录 |
| TMDB | API Read Access Token 用于资料；网页登录生成用户 session，用于整部评分写入与删除 |
| MyAnimeList | Client ID，回调 `anishelf://oauth/mal` |
| Bangumi | 个人访问令牌，提供账号验证登录按钮 |
| OpenAI / DeepSeek | API Key；DeepSeek Key 同时用于联网作品名查询 |

书籍搜索、详情刷新与旧资料库类型补全统一识别漫画和小说（包括 MAL 的 light_novel／novel）；类型缓存保留在备份中。书籍跨平台自动匹配与批量导入共用 AI 判断和联网别名回退；传入类型、系列标记、卷数、话数与简介，先排除已知漫画／小说冲突及系列／单卷冲突，再确认作品与版本。批量导入 Bangumi／MAL 书籍时查找 AniList 主条目，保留来源关联；手动匹配显示具体书籍类型。

Bangumi 搜索携带已配置令牌，影视搜索包含动画和三次元。影视收藏请求不再发送仅适用于书籍的 `ep_status`／`vol_status`；剧集进度通过剧集收藏接口更新。

资料库、平台片单及诊断存储于 SQLite。进度编辑只有点击保存才写入本机和同步队列。完整备份使用 .taleqube，包含资料库、关联、队列、译文、观看记录、片单、偏好、诊断、平台凭据和云同步密钥。可设置密码加密整个备份；无密码的备份包含可读取的密钥。图片按需重新缓存。错误与警告日志导出范围为“上次成功导出之后”与“最近 24 小时”的交集；取消导出不推进记录点，导出期间新产生的事件保留到下次。日志移除令牌及密钥，不保存 URL 查询参数。

## 应用图标

`Taleqube/Resources/AppIcon.icon` 是原生 Icon Composer 分层图标，以立方体顶面、书页面和播放屏幕面组成三个矢量图层。Xcode 的 Debug、Release 均使用 `AppIcon`，液态玻璃材质由系统渲染，适配默认、深色、着色和透明外观。品牌源文件与预览保存在 `Design/Brand/`；修改图标时直接用 Icon Composer 打开 `.icon` 文件。

### 作品详情动态主题

详情按图片色群占比、相近色相与彩度选择主题色，以 OKLCH 生成背景、卡片和文字色阶。设计参考 Google Material Color Utilities 的种子色评分与色调角色划分（https://github.com/material-foundation/material-color-utilities），使用本地实现，无新增依赖。完整画面的线性亮度和暗像素占比独立保留；深色作品可在系统浅色下启用详情深色外观，系统深色始终优先。黑白作品保持灰阶。

横图、作品背景、海报依次作为取色来源，下载失败继续回退。详情、页头、卡片和文字共享同一次采样，来源或缓存版本变化会重新采样；取消的旧请求不覆盖新主题。主文字对四类主题表面的对比度至少 7:1，辅助文字与强调色至少 4.5:1；系统增强对比度时提高到 7:1。深浅切换不插值，避免过渡中出现低对比度文字。

`Scripts/check-language.sh --artwork-only` 可独立执行取色验证，包含 864 组配色的对比度、色域、渐变中间色和深色亮度约束，以及黑白、暗蓝、亮黄、暗底亮色图片的取色验证。
