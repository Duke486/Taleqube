# 架构与数据

## 入口和职责

`App/AniShelfApp.swift` 创建 `AppStore` 和 `TrackingStore` 并注入视图环境；`Features/TrackingView.swift` 组织主导航，其中 `NativeShelfNavigation` 通过 `UIViewControllerRepresentable` 包装系统 `UITabBarController`。`AppStore` 管理 AniList 登录和浏览状态，`TrackingStore` 管理本机资料库、平台数据、关联与同步。SwiftUI 视图在 `Features/`，领域模型、API 和服务在 `Core/`。

| 模块 | 主要职责 |
| --- | --- |
| `Core/Tracking.swift` | 作品、个人记录、平台 API、持久化和同步队列 |
| `Core/LibraryIdentity.swift` | 主身份、导入合并、季级状态和评分等规则 |
| `Core/ContentMapping.swift` | 版本化季集映射、校验和进度投影 |
| `Core/SeasonMatching.swift`、`MatchingMetadata.swift` | 季集匹配、多轮补证与元数据读取 |
| `Core/Intelligence.swift`、`MediaLanguage.swift` | 模型请求、搜索补证、翻译和别名 |
| `Core/Artwork.swift`、`Features/Poster.swift` | 季集、图片元数据、图片缓存和主题色 |
| `Core/Authentication.swift`、`PlatformLogin.swift` | 钥匙串、授权和平台登录 |
| `Core/Diagnostics.swift` | 诊断记录与导出 |

## 主要数据对象

`Work` 表示某个来源的作品，身份由平台、类型和远端 ID 组成。`TrackingRecord` 保存主作品、本机评分与进度、来源记录、季级 `ViewingUnit` 和平台关联。`PlatformAssociation` 描述关联目标及范围，`ContentMapping` 保存具体季集关系。`ProgressDraft` 单独保存未提交的编辑；`Delivery` 保存同步目标、字段、状态及尝试记录。`Backup` 聚合资料库和同步等数据，完整应用备份还包含平台快照、偏好、凭据和草稿。

`WorkspaceView`、`BrowserView` 和 `MediaDetailView` 构成另一组 AniList 浏览界面；当前应用入口是 `TrackingView`。定位实际流程时应从入口沿调用关系追踪。

## 数据流

发现或平台片单 → 搜索、选择作品 → 确认主身份 → 明确入库或保存个人记录 → 本机持久化。影视主身份是 TMDB，书籍主身份是 AniList；来源身份和来源进度仍保留。详情优先复用已确认的主身份；非 TMDB 影视详情先等待匹配，失败或等待三秒后加载来源详情，匹配后续成功仍切换 TMDB。

平台关联把来源条目与主作品的覆盖范围连接起来。季归属可以先保存用于评分；进度同步需要有效的集对应。评分和进度分别处理，映射变化会使旧同步任务失效。详见 [匹配与内容映射](匹配与内容映射.md)。

## 存储和外部服务

资料库、平台片单、草稿和诊断以 JSON 原子写入，保留上一版本；损坏时尝试恢复，保存失败回滚内存，检测到其他实例修改时拒绝覆盖。完整备份包含记录、关联、队列、译文、偏好和账号密钥；密钥在备份中为明文，平时存于系统钥匙串。图片按需重新缓存。

设备直接请求 TMDB、AniList、Trakt、Bangumi、MyAnimeList，以及配置的 AI 服务。图片有磁盘和解码内存缓存；横图地址与季资料另有持久缓存。译文按原文变化失效。诊断导出移除密钥、令牌及 URL 查询参数。

### 保存、草稿与重试

`TrackingStore` 启动时读取 `tracking-v1.json`，迁移旧身份与季结构，补齐缺失日期；`platform-library.json` 保存 AniList／Trakt 片单快照，并用令牌指纹隔离账号；`progress-drafts.json` 保存未提交草稿。关联对未入库作品也可缓存，草稿恢复时重新合并最新关联。主库写入前比较上次提交的文件字节，避免其他实例的修改被覆盖。

详情保存先提交本机记录，再针对变化字段生成 `Delivery`。季进度、平台进度及评分分别构造载荷；重试时重新读取最新记录并重新计算，关联被移除或关闭时清理失效任务。清除错误计数只确认当前错误，不执行重试。

评分界面使用百分制，但 `TrackingRecord.score` 及平台适配层仍以十分制保存；发送 AniList 时转换为百分制，TMDB 按半分刻度，其余平台按整数换算。

完整备份为版本 2；导入先验证结构、草稿及诊断，再写文件和凭据，失败时恢复已改内容。版本 1 旧资料库按缺项合并。全平台删除按关联目标逐个执行，Bangumi 跳过，其他目标失败时保留本机记录以便重试。
