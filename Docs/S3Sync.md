# 七牛 S3 云同步

## 连接与操作

设置 → 数据 → S3 云同步。填写七牛 S3 服务地址、S3 空间名、Access Key、Secret Key 和 Region ID。华东示例为 `https://s3.cn-east-1.qiniucs.com`、`cn-east-1`，实际值以桶所属区域为准。粘贴七牛区域的 HTTP 地址时，应用使用对应的 HTTPS 地址连接。

支持自动、Path-style、Virtual-hosted 寻址。单次请求默认 30 秒，并发上限默认 4，TLS 验证默认开启。可先执行“测试连接与读写”；测试对象使用 `anishelf/v1/probes/` 前缀，完成后尝试删除。正常同步需要 List/Get/Put 权限，不通过 Delete 删除业务对象。

启动与回前台立即执行差异同步。入库或关联操作停止 10 秒后同步；保存评分或进度后立即触发，已有同步进行时会补跑。后台定期检查和“立即同步”仍可接收其他设备的修改。列举、传输、提交编解码、资料库合并和凭据读写在后台执行。设置页展示阶段、下载进度、待上传数、传输量、上次成功时间、错误、最近 100 条日志、并发版本和平台投递历史。

“复制全部 S3 设置（含密钥）”会复制当前表单的全部字段；在另一台设备选择“粘贴并导入 S3 设置”后，应用校验配置并将密钥写入钥匙串。Base64 文本可直接解码读出密钥。

“消除所有冲突并以本机为准”需要确认。应用发布经上传校验的本机快照；其他已更新客户端在下一次同步时采用新代次，并清除旧的冲突分支及未上传修改。设备本地的显示偏好保留。旧版本 Taleqube 需要升级才能加入新代次。

## 创建加密资料库与添加设备

连接设置中的「创建加密云资料库」以本机已保存数据创建新库。新设备粘贴同步加入码即可验证并加入，加入码包含 S3 连接和加密密钥。旧明文空间不会自动迁移或删除。

## 数据协议

`anishelf/v1/journal/<SHA256>.json` 保存不可变提交。内容摘要作为对象名；上传后 GET 校验成功才清除本地 outbox。响应丢失时可重复上传相同内容。无需 If-Match、共享 HEAD 或七牛原生 API。

每项操作包含设备 ID、持久化递增序号、字段、前置版本、修改时间和值。全量覆盖发布 v2 快照并开启新代次；后续提交携带代次，接收端只应用当前代次的操作。云端旧日志作为历史保留，旧客户端迟到的写入不会重新引入冲突。删除用显式空值表示。各端完整分页扫描，只下载未处理的提交；完整扫描结束后才应用暂存批次。事务内检查前置版本和无环性，缺少前置版本时保留暂存区，等待下次扫描补齐。

资料库修改与 outbox 在同一 SQLite 事务提交。后续保存只编码变化的作品和字段。云端应用后更新基线，防止回声上传；无序集合使用规范化编码。不同字段合并，有因果关系时后继胜出，同字段并发版本保留；并发删除优先隐藏，人工映射优先于并发自动映射。用户选择版本会生成新的操作，保留原始历史。

## 范围

同步资料库、作品元数据、作品及季级进度和评分、平台关联与映射、人工锁定、无条目标记、中文名及来源、持久化观看历史、已处理历史标识、书籍格式和用户偏好。简介翻译与搜索翻译缓存、图片文件不上传。

应用凭据按服务成组保存，避免混合 access/refresh token。 Trakt／MyAnimeList 在本机也使用单个钥匙串项目原子保存完整凭据组；首次修改时自动读取原有独立项目并转存，迁移中断后以已提交的完整组为准。凭据读取失败会保留观看历史与平台缓存并提示错误，不按退出登录处理。登录、刷新、手动保存和断开连接成功后，连续凭据修改等待 1 秒合并触发同步；相同值不重复写入钥匙串，云端回写后无差异时不触发回声同步。账号页显示凭据待同步、失败和凭据版本冲突；手动保存只提交编辑过的字段，保留页面打开后由云端更新的其他凭据。

账号页按实际账号接口显示未登录、检查中、已登录、登录失效或暂时无法验证；TMDB 读取令牌与评分会话分别验证。启动、回前台、收到云端凭据和本机凭据变动时检查，正常结果复用 15 分钟，临时失败 1 分钟后可重试，也可手动立即检查。设置入口显示失效标记。Trakt／MyAnimeList 的当前访问令牌被拒绝时合并并发刷新请求，自动刷新后验证并重试一次；旧令牌的迟到响应不覆盖新登录。网络失败不会清除凭据，AniList 失效也保留登录信息供重新授权。设备本地使用 Keychain。当前页面、封面及剧照／剧集缩放、图片缓存容量只留在本机；旧日志里的这类偏好也不再应用。AniList Client ID 仍同步；S3 连接配置按设备归档，不让远端配置自动切换本机正在连接的桶。平台投递记录用于跨设备查看，远端记录不会直接加入本机执行队列。

旧协议对象包含可还原的账号凭据；加密协议使用独立资料库密钥与 AES-GCM 认证加密。资料库 ID、协议版本、对象类型及内容标识参与认证；内容标识使用带密钥的 HMAC，密钥不写入 S3 对象。

## 加密传输与检查点

加密对象位于 `anishelf/v2/<libraryID>/`：`objects/` 存放压缩后加密的内容分块，`commits/` 存放最后发布的认证清单，`staging/` 用于迁移暂存及作品快照引用，`checkpoints/` 存放已覆盖提交和因果快照。

按内容确定分块边界；投递状态引用独立作品快照。已校验对象记录服务端 ETag，下次上传通过 HEAD 检查相同版本；版本改变或服务不支持 HEAD 时重新 GET 验证。新增分块仍上传后回读认证，全部依赖成功后才发布清单。接收端缓存最多 256 个已认证分块，重用前重新验证，缓存损坏则重新获取；缓存淘汰不影响数据恢复。

每新增 32 个已确认提交生成检查点。检查点省略已被后继取代的操作正文，保留身份、父版本和原内容承诺；当前分支、删除恢复数据、投递历史仍完整保留。接收端优先读取覆盖较多的检查点；新清单携带经过认证的覆盖范围，已全部接收的范围只读清单，不下载快照正文。只有事务合并成功才确认未接收的覆盖提交。离线设备也检查新检查点，即使被覆盖提交已从列表移除；其未发布编辑继续参与因果合并。

“本轮传输”与各分项相加一致，包含上传、下载、校验、列表、其他响应和重试正文。空同步没有业务正文，仍有列表响应；这些数字不包含网络头部和未收到响应的中断请求部分。最近日志记录每轮流量分项。

## 本地结构

- `cloud-registers`：字段的不可变版本及冲突分支。
- `cloud-field-baseline`：逐字段已应用基线。
- `cloud-outbox`：待上传操作。
- `cloud-epoch` 与 `cloud-reset`：当前代次和经校验的权威快照。
- `cloud-inbox`：已下载、尚未整体应用的提交。
- `cloud-checkpoint-pending`：检查点与覆盖范围，和收件箱一起事务提交。
- `cloud-chunk-cache`：经过认证的分块缓存。
- `cloud-settings-pending`：跨 SQLite、Keychain、UserDefaults 的设置恢复意图。
- `state` 中的 `cloud.*`：设备身份、操作序号、目标及接收标识。

不自动删除云端历史、墓碑或未解决版本。等价的 Endpoint 大小写、默认端口和末尾斜线会规范化；切换目标桶会重新排队本机已知操作，避免旧桶的上传确认误用于新桶。

## 验证入口

- `Scripts/check-cloud.sh`：签名、规范编码、乱序、重复操作、加密及 HTTP 传输检查。
- `Scripts/check-cloud-storage.sh`：投影范围、字段增量、事务回滚、持久队列、删除及前置版本。
- `Scripts/check-cloud-integration.sh`：真实协调器连接模拟 S3，验证两设备首次接入、并发修改、响应丢失、列举失败、重连和删除。
- `Scripts/check-cloud-integration.sh --benchmark`：固定种子的合成 100 作品／200 投递记录，比较旧协议与加密协议的首次、空同步及评分修改流量。
- `Tests/NavigationUITests.swift` 中 `testCloudSettingsEntryAndDefaults`：设置入口与表单。

构建通过不等于真实桶验证；实际桶的区域、凭据、权限和 TLS 由连接测试验证。

删除快照保存删除前的完整作品字段，包括当时已清除的评分状态；设置页可恢复整部作品。采用与删除并发的编辑版本时，先恢复完整作品，再应用所选字段。保存当前进度编辑时采用三方合并，保留打开编辑后从其他设备收到的无关字段修改。

启动通过 `PreparedTrackingLibrary` 在后台解码 SQLite 内容图及平台快照，UI store 接收预加载结果。大资料库物化先按作品分组，避免每个作品再次扫描全部字段。

## 原规划尚未实现的部分

- 云端旧提交、无引用内容及明文版本历史的安全回收；当前不会自动删除业务对象。
- 坏提交隔离和无依赖分支的部分应用；当前错误保留本地数据及暂存提交，并报告同步未完成。
- 完整结构化内容图共享、尚未发布操作合并和服务端校验和协商；当前采用作品快照引用、内容分块、压缩及 ETag 复用。
- 实际百部作品资料库的优化前后对照；合成基准不能作为用户那次 40 MB 的实测归因。

## 2026-11-04 合成基准结果

`Scripts/check-cloud-integration.sh --benchmark`：100 个作品、200 条投递，随机正文采用固定种子；导出大小为 310229 B。统计包含已收到响应的请求正文与列表响应。

| 场景 | 旧协议 | 加密协议 |
|---|---:|---:|
| 首次同步 | 4815019 B | 2407978 B |
| 空同步 | 190 B | 291 B |
| 修改一个评分 | 812 B | 1189 B |

两种协议的空同步均无业务正文，表中空同步数值全部来自发现请求的列表响应。小评分操作的加密封装有固定开销；改善主要在大内容复用和初始化。另有 180 KB 作品快照的投递状态变更回归，接收流量小于 20 KB，并验证完整还原。

最终验证通过 10 项协议、5 项 HTTP 传输、31 项云存储、73 项集成检查及 iOS Simulator 构建。
