# AniShelf 产品交互约束

- iPad 主导航使用系统侧边栏／顶部 Tab 切换，切换按钮始终可用；导航不随滚动收起或消失。
- 顶部导航的 AniList 与 Trakt 保持两个独立入口，位于资料库之后的系统固定分组，不合并为“平台”菜单。
- 永远不新增单集观看操作：禁止“本集已看／未看”、逐集勾选、单集观看记录，以及在剧集卡片或菜单中新增“看到这一集”等快捷操作。剧集浏览支持资料、图片浏览及跳转 Infuse 播放；跳转不写入单集观看记录，现有作品／季级进度编辑保留。
- 详情页海报与背景横图保持展示用途，不添加点击打开或长按浏览入口。剧照浏览器内图片可全屏浏览。
- 作品详情使用系统缩放 sheet；iPad 详情目标宽度为 700pt，保留较高布局；整部评分置于简介之前，剧照紧随简介。
- 关闭详情时，未保存修改或进行中的 AI 匹配必须询问，未经确认不取消匹配或丢弃修改。
- 手动匹配：点击条目直接确认；允许多选的关联类型通过末尾独立复选框累积选择，批量确认后提交。
- 浏览作品的网格支持双指实时缩放，改变列数并填满可用宽度，保留缩放密度。

- 海报卡片普通点击不显示选中底色；长按只上浮海报，不包含标题和年份。菜单不提供重复的“查看详情”“查看来源”入口。
- 所有观看状态菜单复用海报角标的状态色。
- TMDB 剧集主条目状态仅汇总已标记的正片季，排除特别篇及未标记季；优先级为重温 > 在看 > 计划 > 暂停 = 放弃 > 完成。同级暂停／放弃使用最近一次明确标记；观看进度、标记信息及汇总状态必须持久化本地。
- 剧集、剧照及类似浏览器的关闭转场始终返回最初点击项，内部翻页不改变返回目标。

- 点击选择季、剧集、剧照或其他浏览条目时，保持当前滚动位置，不自动居中或滚动到选中项；全屏分页浏览器保留打开目标的初始定位。

- 所有影视作品均展示 Infuse 相关入口，不受是否入库或是否从最近观看打开的限制，并要求有效 TMDB 匹配。入口放在详情主副标题右侧、季卡片原对号区域、集封面右下角及集详情标题右侧。季选择只用卡片边缘表示；所有入口仅打开 Infuse 对应详情页，不追加自动播放参数，不改变本地观看状态。

- 非 TMDB 来源的影视详情先等待 TMDB 匹配；匹配失败或等待 3 秒后才请求原平台详情数据，超时不取消匹配，后续成功仍切换 TMDB。


# 功能保留与 AI 匹配契约

- 移除、简化、停用现有功能，缩减自动执行范围，降低模型升级／搜索补证／轮次能力，或改变用户微调过的提示词与谨慎度之前，必须先说明具体行为变化并取得用户明确同意。修复性能、卡顿或解析错误不构成删减功能的授权。
- 涉及匹配逻辑时先阅读[匹配与内容映射](匹配与内容映射.md)；不把“果断、减少无效搜索”解释成取消多轮 Agent。
- 关联匹配保留完整链路：轻量元数据初判 → 按缺项读取平台详情、TMDB 季集表／联网搜索 → 多轮补证 → 已配置的 Terra 最终裁决。最多六轮（含首轮）；清晰匹配可提前成功，普通候选首轮否定或未匹配不得直接终止。
- 一对一完整正片季默认逐集对应；拆季／跨季自动进入集对应匹配。保留手动“AI 补全集对应”作为重试入口，不得用它替代自动流程。
- 特别篇单独处理：季相关 OVA／OAD／SP 必须比对实际 S00 集标题、简介与平台简介；无法确定具体对应则跳过，不能追加到正片季末，也不为特别篇穷尽六轮。独立 OVA 系列不能仅凭发行格式强制归 S00。
- 普通季归属不苛求完美外部交叉引用；最终裁决允许依据一致的标题、简介、季／分部、日期和集表合理推断，不虚构 ID，不改变人工锁定。评分、进度仍以 TMDB 为准。

# 马尾原则（2026-11-04）

- 用最小的完整改动解决实际问题，优先复用项目已有实现和标准库，不新增无需求的抽象、配置、依赖或兼容层。
- 修改共用逻辑前检查全部调用方；实现、调用方、迁移和必要回归一起收尾，不把每个小步骤当作交付。
- 不以精简为由删减现有功能、数据、校验、错误恢复或用户授权范围；功能变更仍遵守上面的授权契约。
- 先完成同一问题的实现，再集中运行相关验证；只针对实际失败追加修复与复测，避免每改几行就重复整套测试。
- 性能结论必须对应可复现的测量场景，区分合成数据与实际用户数据；明确记录未完成项，不把部分测试通过写成整个计划完成。
