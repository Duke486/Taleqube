# S3 加密云同步与本地备份

## 准备存储空间

准备一个支持 S3 API 的私有存储空间。应用以七牛 S3 为优先适配目标，也提供 Path-style 与 Virtual-hosted 寻址；其他 S3 兼容服务请先运行应用中的读写测试。

在设置 → 数据 → S3 云同步 → 手动设置同步／连接设置，填写：

| 字段 | 填写内容 |
| --- | --- |
| Endpoint | 存储空间所在区域的 HTTPS S3 服务地址 |
| Bucket | 空间名，非文件夹名 |
| Region | 桶所属 Region ID |
| Access Key / Secret Key | 自己的存储凭据 |
| 寻址方式 | 自动，或按服务要求选择 Path-style / Virtual-hosted |

七牛华东示例为 `https://s3.cn-east-1.qiniucs.com` 与 `cn-east-1`，请按自己的桶区域填写。七牛区域地址填写成 HTTP 时应用会规范化为 HTTPS。保留 TLS 证书验证。

正常业务需要 List / Get / Put；「测试连接与读写」会创建探测对象并尝试删除，Delete 用于探测对象清理。请让凭据只访问所需桶／前缀。

## 第一台设备：创建加密库

1. 先确认本机资料库内容正确，并导出一份本地备份。
2. 保存 S3 设置，执行「测试连接与读写」。
3. 在连接设置选择「创建加密云资料库」。
4. 执行「立即同步」，确认成功时间和传输状态。
5. 保存「资料库恢复码」，用于恢复加密资料库。

加密协议使用独立资料库密钥和 AES-GCM 认证加密。密钥不写进 S3 对象。创建新加密库不会自动删除旧明文空间与旧对象。

## 其他设备：加入同一资料库

1. 在已连接设备选择「复制同步加入码」。
2. 在新设备的 S3 云同步页面选择「粘贴加入码或恢复码」。
3. 导入并加入，执行立即同步，检查资料库与账号状态。

加入码包含 S3 连接与解密能力，恢复码也能恢复资料库；仅在自己的设备间传递，勿放入 Issues 或公开截图。「复制全部 S3 设置（含密钥）」同样包含可还原的密钥，Base64 不等于加密。

## 何时同步、同步什么

启动与回前台会执行差异同步，保存评分或进度后立即触发；其他资料库与关联修改在停止操作后合并同步。也可手动立即同步。系统后台调度机会由系统决定。

同步包括资料库、作品与季级评分进度、平台关联及内容映射、人工锁定、观看历史、中文名与账号凭据等。图片和简介／搜索翻译缓存不上传。当前页面、封面和浏览缩放、图片缓存容量等显示偏好保留在设备本地。

## 冲突与恢复

- 遇到同字段并发修改，在冲突列表查看版本并选择采用。
- 「用本机资料库替换云端」会发布本机权威快照；其他设备下次同步将采用新代次，并清除旧冲突分支与未上传修改。操作前确认本机内容及备份。
- 「放弃本机冲突并以云端为准」先获取最新云端资料，再对冲突采用云端版本。
- 删除的作品可在恢复区域查看并恢复。
- 错误时先检查 Endpoint、Region、桶权限、密钥和网络，查看最近同步日志，再重试。

应用当前不自动回收云端历史业务对象。不要自行删除仍被当前资料库引用的对象；恢复密钥丢失后无法解密现有加密库。

## 本地完整备份

在设置 → 数据中导出 `.anishelf`，建议设置备份密码。完整备份包含资料库、关联、队列、译文、观看记录、片单、偏好、诊断、平台凭据与云同步密钥；图片按需重新缓存。

不设密码的备份含明文密钥。导入前核对摘要与目标设备，按界面确认替换。S3 跨设备同步和完整备份覆盖范围不同，升级或大范围替换前保留独立备份。

协议与开发细节见仓库 [Docs/S3Sync.md](https://github.com/Duke486/AniShelf/blob/main/Docs/S3Sync.md)。
